# Проверка клиента на Авроре

Сборка 0.1-34 собрана для эмулятора Aurora OS 5.2.1.200 x86_64. Подробности восстановления камеры приведены в CAMERA-DIAGNOSTICS.md.

## Проверено в эмуляторе

- Вкладки «Недавние», пустой «Календарь» и «Настройки» открываются. Из профиля работают «Применить», возврат и нижняя навигация.
- Поле сервера пустое с подсказкой https://meet.jit.si. Старое сохранённое значение этого адреса преобразуется в пустое поле. При входе в комнату пустое значение разрешается в сервер meet.jit.si.
- В настройках видны переключатели и заголовки по присланному образцу; лишние меню и подписи удалены.
- На экране перед входом показана живая камера эмулятора. После передачи управления встрече видео во встроенном Jitsi появляется автоматически. При выходе приложение возвращается на экран перед входом, затем к комнатам.
- Экран звонка и список участников открывались после обновления оформления; камера работала внутри встречи. В списке были показаны два участника. Отправку и получение сообщений между ними отдельно не проверяли.
- Кнопка «Пригласить» вызывает ShareAction Авроры и копирует ссылку. В эмуляторе системное меню отправки не открылось: в нём не установлены приложения для отправки. Передачу ссылки через это меню и вставку из буфера нужно проверить на устройстве.
- Экран «Инфо» запросил реальные номера и ПИН для комнаты в эмуляторе. Полученные значения совпали со снимком iPhone. Локальные SVG флагов корректно отобразились в сборке 0.1-34.
- Вход организатора открывает встроенную страницу авторизации. Сам вход в учётную запись не выполнялся.
- Gravatar: код нормализует email и формирует SHA256-ссылку согласно документации. Эмулятор получил HTTP 200 для публичного профиля; тест Qt в SDK скачал и декодировал изображение. Отображение с личным email пользователя не проверялось.
- Автоматические проверки логики приложения и JS моста проходят. Они не заменяют проверку звонка с двумя участниками.

## Требует проверки на устройстве

- Управление чатом и участниками во время звонка с двумя участниками.
- Открытие системного меню отправки ссылки на устройстве.
- Работа камеры и звука при блокировке устройства и смене сети.
- Альбомная ориентация и большие системные размеры текста.
- Телефонный вход на сервере проекта: наличие API, корректность номеров и ПИН, переход по телефонной ссылке.

## Архитектура

Экраны написаны на Qt/QML. Конференция и серверная авторизация работают во встроенном Chromium через Jitsi IFrame API. Локальная HTML-страница соединяет API Jitsi с приложением через loopback и случайный адрес для каждой встречи. Настройки, комнаты и профиль хранятся в QSettings. Имя/email профиля не заменяют логин/пароль сервера.
